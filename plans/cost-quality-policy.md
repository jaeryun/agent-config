## 목표와 범위

메인은 사용자가 선택한 모델·effort를 유지하면서, 요청한 결과의 정확성·완성도·유지보수성과 필요한 검증을 충족한다. 그 조건 안에서 호출 단가가 아니라 조사·인계·재시도·검증·재작업을 포함한 완료까지의 총비용과 불필요한 지연을 줄인다. 짧은 출력, 낮은 토큰 수, 높은 캐시 적중률 자체를 성공 기준으로 삼지 않는다.

이 저장소의 범위는 프롬프트·필요한 skills·OMP role 설정이다. 이번 제안은 기존 프롬프트의 판단 기준을 보완한다. 모델 교체, 자동 메인 라우팅, 새 역할·skill·hook, 캐시 예열, telemetry, 벤치마크, OMP 내부 구현 감사는 추가하지 않는다. 현재 모델 배정과 이미지 전담 정책도 유지한다.

## 변경 계획

### 1. 메인 목표를 명시한다

`agent/AGENTS.md`의 서두에 다음 의미를 짧게 추가한다.

- 정확성·완성도·기존 설계와의 일관성·필요한 검증은 비용 절감을 위한 양보 대상이 아니다.
- 해당 기준을 충족하는 방법 중 총 작업량과 인계·재작업을 줄이는 경로를 선택한다.
- 사용자가 정한 시간·비용 제한과 품질·범위가 양립하지 않을 때만 실질적인 선택을 묻는다. 임의로 범위를 축소하거나 완료를 주장하지 않는다.

### 2. 역할 선택과 실패 대응을 보완한다

기존 작업 배분 표와 위임 절차를 대체하지 않고 해당 항목에 결합한다.

- 간단한 수정은 이미 문맥을 아는 메인이 직접 처리한다. 경량 모델 호출 자체를 위해 위임하지 않는다.
- 반복적이고 방법이 확정된 작업은 경량 역할에 맡길 수 있다. 원인이 열린 문제나 중요한 계약 변경에는 적합한 판단 능력을 가진 역할을 처음부터 사용한다.
- 독립적인 병렬 작업은 시간·문맥 분리에 이점이 있을 때 사용한다. 병렬화가 토큰이나 비용을 자동으로 줄인다고 가정하지 않는다.
- 같은 접근이 새로운 근거 없이 실패하면 횟수를 채우기 위해 반복하지 않는다. 기존 시도·오류·결정·부분 변경을 보존하고 메인 또는 `deep`이 이어받는다.
- 독립 리뷰는 위험이나 요청에 맞춰 사용하고, 유효한 증거가 있는 unchanged 경계의 검사를 불필요하게 반복하지 않는다.

### 3. 문맥 재사용과 캐시 고려를 구분한다

기존 후속 작업·공통 context 항목을 보완하고, 짧은 캐시 경계 항목을 둔다.

- 같은 범위의 수정·질문은 기존 작업자에게 변경분과 미해결 사항을 전달한다. 새 주제, 독립 검토, 기존 접근에서 벗어나야 하는 경우에는 필요한 근거를 추려 새 문맥에 전달한다.
- 공통 지침·계약은 불필요하게 다시 표현하거나 순서를 바꾸지 않고, 작업별 변경분을 분리한다. 이는 모델이 작성하는 인계 내용에 대한 규칙이며 런타임의 요청 순서·시스템 접두부를 제어하라는 지시가 아니다.
- 원문·긴 결과는 기존 artifact를 재사용하고 필요한 요약·경로·구간만 전달한다. 목표·제약·중요한 예외·근거·불확실성을 생략해 토큰을 줄이지 않는다.
- 세션 재사용, 조사 결과 재사용, provider prompt cache를 구분한다. 기존 세션이 항상 저렴하거나 새 세션이 반드시 cache miss라고 단정하지 않는다.
- 캐시를 위해 오래된 문맥을 무조건 유지하거나 필요한 문맥 정리를 막지 않는다. 캐시 예열·TTL 유지용 요청, 임의 모델·effort 변경은 하지 않는다.
- usage가 이미 제공될 때 입력·출력·cache read/write를 구분해 참고한다. 단가·과금 방식·캐시 수치가 없으면 비용과 절감률은 미확인으로 둔다. 비용 계산을 위한 추가 작업이나 매번 사용량 보고는 요구하지 않는다.

### 4. 작업자와 설명을 맞춘다

- `agent/agents/deep.md`: 새 정보 없는 반복 탐색을 피하고, 비용 때문에 원인 분석·필요한 검증을 생략하지 않는다는 짧은 기준을 기존 approach·verification 항목에 결합한다.
- `agent/agents/image-analyst.md`: 기존 관찰 재사용과 필요한 추가 분석 허용은 유지한다. 정책 중복이나 일률적인 해상도 저하·검증 축소 규칙은 추가하지 않는다.
- 기본 task·sonic·scout·reviewer 프롬프트는 복제하지 않는다. 작업별 제약과 필요한 효율 기준은 현재 인계 계약에 따라 전달한다.
- `README.md`: 목적·적용 기준·참고 revision·캐시의 통제 범위를 갱신한다. 절감률이나 품질 향상을 실측한 것처럼 기록하지 않는다. 기존의 “전역에 설치하지 않았다”는 문장은 당시 확인 이력임을 날짜와 함께 구분하고, 이미 링크된 설치에서는 저장소 프롬프트 수정이 다음 로딩에 반영되는 반면 미설치 checkout은 그렇지 않다는 점을 명시한다.
- `agent/config.yml`, `scripts/install.sh`: 이번 정책 보완으로 변경할 필요가 없다.

## 확인과 적용

2026-10-13 사용자 승인으로 실행했다. `agent/AGENTS.md`와 `agent/agents/deep.md`의 전역 링크가 저장소 파일을 가리키는 것을 확인했으며 변경은 다음 로딩에 반영된다. 이미 로딩한 세션까지 갱신된다고 가정하지 않으므로 새 세션에서 사용한다. 모델 설정과 설치기를 변경하지 않아 설치기는 다시 실행하지 않았다.

1. 아래 대표 상황에 대해 지침이 모순되는 결정을 강제하지 않는지 정적으로 검토한다. 고정 테스트 스위트나 모델 벤치마크는 만들지 않는다.
2. OMP의 모델 요청 없는 RPC 로딩으로 변경된 지침과 role 로딩을 확인한다. 이는 프롬프트 전달 확인이지 에이전트 행동·캐시 적중·청구액 절감의 증명이 아니다.
3. 실제로 수정한 문서와 확인 범위, 사용자 전역 링크의 반영 시점을 보고한다. OMP 내부 신뢰성 검증은 수행하지 않는다.

| 대표 상황 | 지침이 유도해야 할 결정 |
|---|---|
| 작은 설정값 수정 | 직접 처리하고 관련 확인만 한다. 비용 분석·작업자·리뷰를 추가하지 않는다. |
| 범위가 정해진 반복 수정 | 위임의 실익이 있으면 경량 작업자에게 명시적인 변경 규칙을 전달한다. |
| 원인이 불명확한 중요한 오류 | 적합한 메인/고난도 역할이 판단한다. 저가 작업자의 실패를 일부러 누적하지 않는다. |
| 같은 기능의 후속 결함 | 기존 담당자에게 오류와 변경분을 전달하고 유효한 발견을 재사용한다. |
| 관련 없는 새 작업 또는 독립 검토 | 필요한 근거만 전달해 분리하고 캐시 때문에 기존 작업자 재사용을 강제하지 않는다. |
| 긴 공백 후 재개, 캐시 수치 없음 | 적중·절감률을 추측하지 않고 필요한 작업만 진행한다. |
| 비용 제한과 완료 기준 충돌 | 범위를 몰래 줄이지 않고 사용자가 결정해야 할 선택을 설명한다. |

## 리뷰 기준

## Astra max 리뷰 결과

2026-10-13, OMP의 `openai-codex/gpt-6-astra`와 `thinking=max`로 별도 읽기 전용 리뷰를 수행했다. Codex 실행 경로가 `max`를 지원하지 않아 OMP 경로를 사용했으며, 모델 요청 없는 설정 조회에서 Astra와 max 선택을 확인한 뒤 해당 인자로 리뷰 세션을 시작했다. 낮은 effort로 대체하지 않았다.

- **판정: APPROVE.** 차단 결함이나 필수 수정 요구는 없었다.
- **선택적 의견 1건 채택:** README의 과거 미설치 기록과 현재 전역 링크 상태를 구분하라는 의견을 변경 계획 4번에 반영했다. 구현자가 프롬프트 수정을 로컬에만 머무는 변경으로 오해하지 않도록 한다.
- **유지할 판단:** 품질·완료 기준 우선, 완료까지의 총비용 고려, 메인 모델 선택권, 기존 역할 배정, 문맥 재사용과 provider 캐시 구분, 구독 과금의 불확실성, 기존 문단에 통합하는 소규모 변경.
- **추가하지 않을 것:** 자동 메인 라우팅, 저가 모델의 고정 실패 횟수 강제, cache warmer, 상시 문맥 유지, 비용 대시보드·벤치마크, 필수 다중 리뷰.
- **검토 범위:** 계획과 현재 프롬프트·설정·README, 명시된 Oh My OpenAgent revision 및 공식 provider 캐시 문서를 대조했다. Oh My ClaudeCode는 참고하지 않았다. 리뷰어는 파일 수정·설치·테스트·OMP 내부 감사·추가 위임을 수행하지 않았다.

리뷰 승인은 계획의 일관성과 범위에 대한 판단이며, 실제 품질 향상·캐시 적중·비용 절감의 실측 결과가 아니다.

- 대표 상황을 정적으로 대조해 작은 작업의 직접 처리, 위험에 맞는 역할 선택, 후속 문맥 재사용의 예외, 근거 없는 캐시·과금 추정 금지, 예산·범위 충돌 시 사용자 결정이라는 기준을 반영했다.
- 실제 전역 링크와 모델 요청 없는 OMP RPC `get_state`에서 총비용·품질 목표, 캐시·구독 과금 경계, 사용자 메인 선택권과 커스텀 작업자 목록이 로딩되는 것을 확인했다. 메인은 기존 `@default`인 Sol high로 로딩됐다.
- 임시 확인 디렉터리는 정리했다. 실제 모델 행동·캐시 적중·비용 절감은 측정하지 않았고 이를 통과로 주장하지 않는다.
